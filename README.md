# 幸运转盘 · Lucky Wheel

一个单文件实现的决策小工具：转盘、抛硬币、丢骰子、随机数字。手机上可以装成独立 App，断网也能用。

## 这是什么

「今天吃什么」「谁去拿外卖」这类纠结，交给它转一下。整个应用就是**一个 `index.html`**，没有框架、没有构建步骤、没有任何依赖——下载下来双击就能跑，改一行刷新就能看到效果。

## 功能

**转盘**
- 多个转盘并存（最多 20 个），标签双击改名；每个选项可设**权重**，权重高的扇区更宽、更容易被抽中
- 选项可以挂**扇形贴图**：内置裁剪编辑器，按扇形的真实张角裁图，两种贴图方式——整块铺满（图就是扇形本身）或整张留边
- 选项可以设**跳转**：转中后一键跳到另一个转盘，或跳到硬币 / 骰子 / 数字页
- 支持「转中后自动移除该选项」，适合淘汰制

**外观**
- 10 套内置主题，自定义主题支持 2~12 个颜色任意排，或「单色渐变」（给一个颜色，按选项数自动生成深浅）
- **每一块扇形可以单独上色**：12 个推荐色、6 个渐变预设（由盘心向外过渡）、或自己挑主色 + 副色做任意双色渐变；不挑就跟随主题，两种方式可以混着用
- 盘面字体 6 种（雅黑 / 黑体 / 宋体 / 楷体 / 圆体 / 等宽）、文字颜色 4 种方案（浅色自动配黑描边、深色自动配白描边）、指针 4 种样式（细针 / 大箭头 / 圆点粗针 / 盘外顶部标记），所有指针共用同一个轴心

**音效**
- 转动、跳齿、抛硬币、丢骰子、随机数字、出结果，各自独立音色；4 种音效风格，纯 Web Audio 合成，不加载任何音频文件
- 1 根总音量 + 6 根单项滑杆，滑到 0 就是静音
- 可以给每个音效**导入自己的音频文件**，导入时自动量峰值做归一化，不会一个震耳一个听不见

**分享**
- 分享码连**贴图、硬币图、自定义音效、音效风格和音量**一起带走，对方导入后看到的就是一模一样的盘
- 带媒体的码用 `deflate-raw` 压缩；媒体按内容去重，同一张图只存一份
- 码太长贴不下的，可以「存成文件」发文件，对面「从文件导入」

**其它**
- 界面大小三档（标准 / 大 / 特大），触屏设备默认「大」，按钮和触控区一并放大
- 全部数据存在本机 `localStorage`，**不上云、不登录、不联网**，分享全靠分享码
- PWA：可装到桌面、断网可用；安卓还能用 PWABuilder 打的 APK 装成独立 App

## 怎么用

**直接在浏览器里用**：打开上面的在线版。装到桌面/主屏幕的入口在页面里，iPhone 必须用 Safari（分享 → 添加到主屏幕）。

**自己跑**：把仓库下载下来，双击 `index.html`。要用到 PWA / 离线 / 分享码压缩这些能力，得用本地服务器打开：

```bash
python3 -m http.server 8000
# 然后访问 http://localhost:8000
```

**改它**：`index.html` 里搜 `BUILTIN_THEMES` 加主题，搜 `SLICE_PICKS` / `SLICE_GRADS` 改推荐色和渐变预设，搜 `SFX_LEVEL` 调音效响度基准。改完把 `sw.js` 的 `CACHE_NAME` 版本号 +1，否则用户那边可能还在用旧缓存。

## 技术说明

| 部分 | 做法 |
|---|---|
| 结构 | 单个 `index.html`，内联 CSS + 原生 JS，零依赖、零构建 |
| 数据 | `localStorage`，键 `wheel_app_state_v2`；写入前一律过 `createItem` / `createTheme` / `validateTab` / `validateAppState` 校验，坏数据整条拒绝而不是静默改值 |
| 类型 | JSDoc `@typedef` + `Result<T>`（`Ok` / `Err`）+ `Object.freeze`，模仿 C# 的不可变模型 |
| 盘面 | Canvas 2D，逐扇区 `clip` + 渐变填充；贴图先把画布 `rotate` 到扇形标准姿态再按外接矩形 cover 铺满，保证每块内容方向一致 |
| 声音 | Web Audio 现场合成（噪声 + 振荡器，5ms 起音 + 指数衰减），峰值统一配平到 −20…−11 dBFS，不削波 |
| 分享码 | `WHEEL2.` + base64url（deflate-raw 压缩）/ `WHEEL2R.` 裸 JSON；兼容旧 `WHEEL1.` 的 v1、v2 |
| 离线 | Service Worker：页面**网络优先**（打开就是最新版，断网回退缓存），图标等静态资源缓存优先 + 后台更新 |

分享码 v3 的负载形状（看代码时对得上）：

```js
{
  v: 3,
  w: [{ n: 名称, t: 主题id, r: 0|1, i: [[名字, 权重, 跳转, 贴图键, 颜色]] }],
  th: { 主题id: { n, c: [颜色...], g: 渐变基色 } },
  m:  { m1: { t: 'image/jpeg', d: '<base64>' } },   // 媒体字典，按内容去重
  sfx: { style, vol, slot, custom },
  cf: 'm2', cb: 'm3'                                 // 硬币正反面
}
```

## 关于这个项目

**这是一个 AI 项目。** 绝大部分代码、文案、测试脚本都是在 AI 协作下写出来的——人负责提需求、试用、挑毛病和验收，AI 负责实现和自查。所以你在代码里会看到大量为「让 AI 和人都能读懂」而写的显式校验和注释，而不是那种压缩到一行的写法。

没有后端、没有数据库、没有账号系统，是刻意这么定的：纯本地就能做到「复制一个码得到一模一样的盘」，再往上加服务器只会变成持续的支出和维护。
